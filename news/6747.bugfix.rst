A failed ``pipenv install <package>`` (for example a package that doesn't exist, or a version that can't be resolved) now restores the Pipfile exactly as it was. Previously a lock failure left the new entry in the Pipfile, and a failed upgrade of a package already in the Pipfile could remove that package entirely. An unresolvable dependency also no longer prints a Python traceback after the resolver's error message; pass ``--verbose`` to see it.
